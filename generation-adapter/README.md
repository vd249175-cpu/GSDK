# GraphVideo Generation Worker

`generation-adapter` is a private Python worker owned by Electron and used by GraphVideo generation WorldNodes. It is not a FastAPI service, does not listen on a port, and is not deployed independently. It owns provider connections and remote handles, but it does not own models, workflows, project DAGs, readiness rules, task state, or SQLite persistence.

Every JSON Lines request performs exactly one operation:

- `health`
- `submit`
- `poll`
- `download`
- `shutdown`

The adapter never advances from one operation to the next by itself. The Node graph decides when to send the next request.

## Development setup

```powershell
cd generation-adapter
python -m venv .venv
.venv\Scripts\python.exe -m pip install -e .
Copy-Item config.example.toml config.toml
```

Electron 优先使用 `generation-adapter/.venv`。首次启动前可执行下面命令核对 Python 依赖、API key 和 provider 可用性；`status: degraded` 会列出不能发射的 provider，不能把它当作可生成状态：

```powershell
.venv\Scripts\python.exe -m generation_adapter check --config config.toml
```

## Start

```powershell
.venv\Scripts\graphvideo-generation-adapter.exe worker --config config.toml
```

Electron starts the worker before constructing `StudioRuntime` and stops it during application shutdown. Generation WorldNodes send separate submit, poll and download effects through one injected operation adapter; the worker never schedules the next step itself.

Comfy Cloud submit uses `client.submit()` and returns its job handle after reference assets are uploaded and the remote job is accepted, without waiting for terminal generation. Do not replace it with `client.run()`: long-running video completion is owned by the graph's separate poll steps, followed by a separate download effect. Electron does not impose one aggregate wall-clock timeout on active upload/download streams; the provider's `request_timeout_seconds` remains the per-request network inactivity boundary.

Cloud jobs may expose preview outputs before reaching a terminal state. Poll reports ready only after a successful terminal status and selects the output matching the requested workflow media. Comfy Cloud can mislabel a real SaveVideo `.mp4` as `type=image` while leaving `content_type` blank, so selection uses a valid content type first, then the committed filename extension, and only then the SDK type. The selected output asset id is carried into download, so a video transfer never falls back to an earlier preview image merely because it is `outputs[0]`.

The example configuration registers two physical providers:

- `comfy`: Cloud mode uses the official `comfy-sdk` workflow and asset APIs; `api_mode = "local"` uses standard `/prompt`, `/history`, and `/view` endpoints.
- `audio`: preserves the current project-scoped Audio Gateway endpoints for SFX, speech, voice design, and voice cloning.

Credentials are named by `api_key_env` and read from the worker environment. Electron sources `COMFY_API_KEY` from its own process environment (with `COMFY_CLOUD_API_KEY` as a legacy fallback); Agent and Codex MCP files are not application credential stores. Comfy Cloud submit passes the same key separately to Partner Nodes such as Seedance via the SDK's per-run `api_key`; it is never embedded in workflow JSON or returned in handles and observations.

Audio Gateway calls may synchronously return generated bytes. Those bytes remain inside this long-lived process and are represented externally by an opaque task handle; they are written only after a separate `download` request.

## Protocol example

Input:

```json
{"requestId":"req-1","operation":"health","payload":{}}
```

Output:

```json
{"requestId":"req-1","ok":true,"observation":{"worker":"graphvideo-generation-adapter","protocolVersion":1,"status":"ready"}}
```

Responses may arrive out of order because independent operations run on a worker pool. Callers must correlate them with `requestId`.
