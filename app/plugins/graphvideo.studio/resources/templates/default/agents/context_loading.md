# 上下文感知与分层载入规范

在 GraphVideo 的多 Agent 协同生产体系中，盲目加载全项目正文或无节制查询会导致上下文窗口被无关数据淹没，并引发幻觉与越权。所有 Agent 必须遵循**分层分职责的上下文阅读原则**、**多种读取形式的自适应动态规划**与**维护描述防事实漂移铁律**。

---

## 1. 分层分职责的上下文阅读原则

- **自身认知与职责驱动**：在接触具体项目前，Agent 首先应阅读自身文档知识并明确工作范围（查阅 `project_knowledge.md`、`self_evolution.md`、具体项目的核心思路及本角色技术细节），明确角色定位与工作边界。进入项目后，仅加载与自身工作和下游交接直接相关的上下文，严禁越界加载不相关的跨职责细节。
- **前沿聚焦与按需回溯**：这是所有 Agent 的通用规则。工作时首先聚焦于当前项目推进的**生产前沿**（当前正在创作、规划或生成的节点/幕次），评估现有上下文是否足以支撑当前创作；若信息不足，再沿着节点拓扑关系与叙事因果向上动态回溯之前的历史设定、剧本、分镜或依赖事实，杜绝脱离项目的凭空猜测。

---

## 2. 分层读取形式与自适应动态规划

项目上下文的获取主要包含三种读取形式：**粗读（宏观拓扑与进度）**用于获取项目全局骨架、通用资产沉淀与分幕制作阶段；**略读（局部注解与依赖分析）**用于读取目标区域节点的描述（`description`），快速把握导演口述意图、分镜画面焦点与拓扑规划，分析并锁定当前任务究竟需要哪些上下文节点支持；**精读（微观事实与细节载入）**用于深入读取直接相关节点的剧本正文（`content`）、分镜正文与参考依赖（如角色底图、风格参数、声纹台词等），获取 100% 确定的生产事实。

**自适应动态跳转机制**：粗读、略读与精读并非死板的线性单向流水线，而是可以根据任务认知状态**自由切换与循环跳转**。在完成任意层级的读取后，Agent 都应**重新评估当前掌握的信息与不确定性**，灵活判断接下来是该进一步下钻精读局部细节、退回粗读重新审视全局上下文、还是转向其他分支略读关联依赖，以最高效地规划并推进任务。在读取过程中不限制特定工具的使用，根据实际需要自由选择合适的查询手段。

---

## 3. 维护节点描述与防止事实漂移的义务（核心铁律）

`description`（描述注解）是所有 Agent 在“略读”阶段快速建立全局态势感知、分析依赖关系的基石。**每个 Agent 都有绝对义务实时维护并更新自己所负责节点的 `description`，确保略读时不发生事实漂移（Fact Drift）**：

| 角色 | 维护的节点类型 | `description` 维护标准与内容 |
| :--- | :--- | :--- |
| **Director (导演)** | `$幕名` | 记录导演口述要点、核心戏剧冲突、情绪基调与关键叙事线索。 |
| **Storyboarder (分镜师)** | `$分镜设计` | 记录分镜核心视听画面、机位景别与关键运镜动作概括。 |
| **Planner (依赖规划师)** | `%镜头`、`@关键帧`、`~音频`、`&风格` | 记录镜头视听目标、关键帧时空锚点、依赖挂载动机与生成模式说明。 |
| **Image Prompter (图片提示词师)** | `@图片`、`~独立音频`、`&风格` | 记录资产中性特征、关键帧捕捉瞬间、声纹人设定位与风格基调。 |
| **Video Prompter (视频提示词师)** | `%视频` | 记录镜头核心动态轨迹、物理运镜变化与声画对位逻辑。 |

### 事实同步铁律
- **内容变更时同步更新描述**：任何 Agent 在通过 `edit_node` 或 `batch_edit` 更新节点的正文（`content`）或生成提示词（`prompt`）时，**必须同时审视并更新其 `description`**。
- **杜绝信息滞后**：严禁出现“正文已大幅改动，但描述仍停留在上一版本”的事实脱节现象，保证整个流水线任何时刻的略读与精读均 100% 严丝合缝。
