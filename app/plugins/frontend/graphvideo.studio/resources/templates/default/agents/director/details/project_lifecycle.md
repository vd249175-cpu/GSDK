# 项目阶段与创作流程

## 适用时机

当开始一次新的故事创作、续写或较大范围改写时使用本文件。

## 开始前

先查询项目结构与相关文本，再判断当前阶段：

- 没有剧本节点，或缺少足以支撑创作的核心设定时，视为“内容稀缺”。
- 已有 `#背景资料`、世界观、角色文本或分幕剧本时，视为“已有内容”。

不要只根据用户一句话判断项目阶段，也不要把“已有一些节点”等同于“上下文已经完整”。

## 内容稀缺时

1. 先与用户对齐故事主题、主要矛盾、剧情走向、角色动机、人物关系和世界规则。
2. 达成共识后，建立 `#背景资料` 及必要的文本节点，例如：

```markdown
<project-structure>
#背景资料
  $世界观与背景
  $角色设定
  $故事大纲
</project-structure>
```

3. 将已确认的内容写入对应节点，不把尚未确认的猜测伪装成设定。
4. 背景足够支撑创作后，完成开篇幕的导演口述与剧本正文。

## 已有内容时

1. 先读取 `#背景资料` 下相关文本节点的描述与正文。
2. 再读取与本次任务相关的已有分幕剧本，梳理剧情推进、人物动机、伏笔和情绪轨迹。
3. 与用户对齐本次新增或修改内容的冲突、人物选择和视听方向。
4. 在不破坏既有连续性的前提下续写或改写。

## 不要

- 不要在背景和人物动机尚未成立时急于堆叠情节。
- 不要为了制造转折而改写既有事实，除非用户明确要求重构。
- 不要一次创建超出当前共识的大量后续幕。

## 完成后

- 将确认过的阶段性结果写入项目并回读核对。
- 告诉用户本次推进到了哪里、保留了哪些待决定问题，以及下一步自然的创作入口。
