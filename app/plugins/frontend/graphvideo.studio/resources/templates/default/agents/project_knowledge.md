# 项目知识与结构规范

本文档是 GraphVideo 所有 Agent 的基础通用规范。在查询、理解、规划、创作或修改项目内容前，必须以此处定义的数据源、目录体系、节点符号与 MCP 工具协议为准。

---

## 1. 基础视频项目目录体系

一个标准的 GraphVideo 项目在磁盘上的物理结构如下：

```text
<项目根目录>/
├── .graphvideo/                  # GraphVideo 内部管理与权威持久化目录
│   ├── nodes.sqlite              # SQLite 数据库：项目的唯一权威事实源（节点树、状态、正文、Prompt、参数与元数据）
│   ├── media/                    # 本地媒体存储目录（生成的视频 .mp4、关键帧/图片 .png、音频 .wav 等）
│   ├── snapshots/                # 项目快照历史库（用户创建的里程碑与逻辑分支快照）
│   └── external-update.json      # 外部文件修改同步信号（跨进程/编辑器同步标记）
└── project.md (可选)              # Markdown Logic 声明视图（用于人类阅读、批量编辑或导入导出）
```

### 数据源与权威性原则
- **SQLite 为唯一权威数据源**：所有节点状态、正文、提示词、依赖拓扑与生成资产均以 `.graphvideo/nodes.sqlite` 为准。
- **Markdown Logic 为声明视图**：`project.md` 是供创作者与 Agent 使用的结构声明与导入导出视图，通过 `run_logic` 或 `write_markdown` 校验并同步到底层 SQLite。
- **本地媒体管理**：媒体文件存放在 `.graphvideo/media/`，UI 与外部协议统一使用 `graphvideo-asset://` 虚拟协议访问，绝对路径不写入 Node 状态或 UI 投影。

## 2. 节点符号与前缀体系

在 GraphVideo 中，节点名称的前缀符号严格决定了节点的物理类型与下游语义：

| 符号 | 节点类型 | 作用与职责 | 缩进子节点的语义 |
| :--- | :--- | :--- | :--- |
| `#xxx` | **结构标签** | 大纲组织、分类与命名空间；纯结构标记，不入库，不生成 Node Store 记录 | 结构层级归属 |
| `$xxx` | **文本节点** | 世界观、角色设定、剧本大纲、分幕剧本、分镜设计、制作说明等纯文本 | **内容展开 (Content)**：子节点是父级文本的细化展开 |
| `@xxx` | **图片节点** | 角色肖像、场景概念图、道具设计、镜头关键帧、空间参考图 | **生成依赖 (Dependency)**：子节点是生成该图片所需的参考要素 |
| `%xxx` | **视频节点** | 镜头动作、分镜视频片段、生成视频 | **生成依赖 (Dependency)**：子节点是生成该视频所需的关键帧、音频、风格或前序镜头 |
| `~xxx` | **音频节点** | 旁白、台词、音效 (Foley)、环境氛围声 (Ambience)、背景配乐 (BGM) | **生成依赖 (Dependency)**：子节点是生成该音频所需的声纹或音频参考 |
| `&xxx` | **风格节点** | 全局视觉基调、色彩光影、镜头渲染风格（正文描述艺术风格与渲染词） | **生成依赖 (Dependency)**：作为其他媒体节点的生成依赖 |

## 3. 项目结构布局与语法规范

### 3.1 项目常见布局结构
在 `<project-structure>` 区域内，一个典型的视频项目通常按以下逻辑组织：

1. **头部区域（通用资产与世界观）**：
   - 通常放置全局世界观背景（`$xxx`）、主要角色肖像（`@xxx`）、核心场景/道具资产（`@xxx`）、全局视觉风格基调（`&xxx`）以及通用声音要素（`~xxx`）。
   - 该部分沉淀可跨幕跨镜头复用的事实基础。
2. **后半部分（分幕与制作工程树）**：
   - 按叙事推进组织各幕/各集内容，包含分幕剧本、分镜设计、分镜头视频、关键帧与专属音效。

```markdown
<project-structure>
#世界观与设定
  $主线背景与核心规则
  @主角肖像_常服
  &赛博朋克写实基调
$雨夜相遇
  $雨夜相遇分镜设计
  %主角步入霓虹雨巷
    @雨中特写关键帧
      @主角肖像_常服
      &赛博朋克写实基调
    ~霓虹雨巷_环境雨声与脚步
$酒吧对峙
  $酒吧对峙分镜设计
  %推门特写
</project-structure>
```

### 3.2 目录组织与命名推荐
- **推荐使用文本节点（`$幕名`）代替结构标签（`#`）组织分幕**：
  在项目的后半部分，推荐直接用 `$幕名` 作为一幕的顶层容器。`$幕名` 本身可作为文本节点承载该幕的剧本正文（`content`）与导演口述（`description`），其缩进子节点（分镜设计、各镜头节点）自然形成从剧本到制作的内容展开。
- **推荐使用直观的语义名称而非纯标号**：
  幕名和镜头名推荐使用具有叙事感、画面感和辨识度的语义标题（例如 `$雨夜相遇`、`%主角步入霓虹雨巷`、`@雨中特写关键帧`），避免使用难以辨别情节的纯序号（如 `$第一幕`、`#Scene01`、`%Shot_001`）。语义名称有助于所有 Agent 快速建立上下文理解，降低误读风险。

### 3.3 核心语法与写入规范
1. **结构标签范围**：项目结构声明必须完整包裹在 `<project-structure>` 与 `</project-structure>` 之间，专注于表达**纯拓扑结构与层级依赖**。
2. **严格 2 空格缩进**：每一层级缩进必须精确使用 **2 个空格**（禁止使用 Tab 制表符，禁止单数空格，禁止跳级缩进）。
3. **节点字段标准修改范式**：
   - 节点的具体内容（`description` 导演口述/规划说明、`content` 剧本正文/分镜设计、`prompt` 生成提示词与参数）存放在 SQLite 中。
   - **标准的写入方式是调用 MCP 工具 `edit_node` 或 `batch_edit`**（例如 `edit_node(selector: "%推门特写", fields: { description: "镜头推进推门动作，门铃清脆响动" })`）。
   - 在 Markdown Logic 中以 `> ` 开头的行仅为 MCP 解析器提供的一种**初始化脚手架语法**（用于在首次全量构建结构时便捷写入注释，存盘时会自动从纯结构树中剥离），并非日常结构声明的正常写法。
4. **禁止手动维护 `id-map`**：节点 ID 由 SQLite 自动分配与管理，严禁在 Markdown 或对话中手写 `id-map`，也不得根据名称猜测 ID。

## 4. MCP 工具与渐进式操作范式

所有项目事实查询与内容修改必须通过 **GraphVideo MCP** 工具完成，严格遵守**上下文安全视口协议**：

### 4.1 渐进式安全查询
1. **顶层结构定位**：调用 `get_structure(depth: 1)` 查看顶层分支与幕结构。
2. **局部视口下钻**：根据任务目标，调用 `get_structure(scope: "<目标节点/幕名>", depth: 1)` 逐步展开局部子树。禁止对全项目直接使用 `depth: 'all'`。
3. **精准字段查询**：结构定位完成后，使用 `query_nodes` 精准读取当前所需的字段（如 `[@主角肖像] :: dc` 或 `[%镜头1] :: dp`）。
   - `d`：描述说明 (`description`)
   - `c`：正文内容 (`content`，用于 `$文本` 与 `&风格`)
   - `p`：生成提示词 (`prompt`，用于 `@图片`、`%视频` 与 `~音频`)

### 4.2 原生原子写入与落盘
1. **单节点无损修改**：优先使用 `edit_node(nodeId, { description, content, prompt })` 传入多行文本，保证 100% 零转义损失并自动同步 SQLite 与 Markdown。
2. **多节点批量修改**：使用 `batch_edit` 一次性更新多个关联节点的字段。

## 5. 全流程 Agent 职责分工与字段归属

| Agent 角色 | 核心产物与归属字段 | 严禁越权操作 |
| :--- | :--- | :--- |
| **Director (导演)** | 设定大纲、`$幕名` 剧本正文 (`content`)、导演口述 (`description`) | 严禁写分镜设计正文、严禁写 Prompt、严禁选择生成模型 |
| **Storyboarder (分镜师)** | `$幕名分镜设计` 正文 (`content`)：机位、景别、视觉画面与运镜要求 | 严禁创建 `@/%/~` 媒体节点、严禁写技术生成 Prompt |
| **Planner (依赖规划师)** | 生成工程拓扑：`%镜头`、`@关键帧`、`~音频`、`&风格` 节点及 `description` 规划说明 | 严禁写技术 Prompt（YAML 头部与正文）、严禁修改剧本/分镜正文 |
| **Image Prompter (图片提示词师)** | `@图片`、`~独立音频`、`&风格` 节点的 `prompt` / `content` 与模型 YAML 参数 | 严禁编辑 `%视频` Prompt、严禁改写上游剧本与分镜 |
| **Video Prompter (视频提示词师)** | `%视频` 节点的时序演化 `prompt`、运镜描述与视频模型 YAML 参数 | 严禁编辑 `@图片` / `~音频` / `&风格` 正文、严禁改动工程拓扑 |
