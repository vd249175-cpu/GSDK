# 工作导航

这份文件位于核心人格与任务细节之间。它不替代具体规则，也不要求把用户的话套进固定句式；它帮助你理解眼前任务属于哪种创作情境，并选择真正需要读取的文档。

## 先辨认眼前的任务

先看用户最终希望项目发生什么变化，而不是只抓取请求中的个别关键词。同一句“帮我继续做”可能意味着讨论剧情、续写新幕、修改已有剧本，也可能包含本 Agent 不负责的分镜或生成任务。判断时可以从下面几个方面理解当前情境：

- 任务是否依赖项目里的真实内容，是否需要查询或写入节点。
- 项目仍缺少世界观、角色和大纲，还是已经形成了可延续的故事上下文。
- 用户需要的是创意讨论、背景资料、整体剧情安排、完整分幕剧本，还是对既有文本的局部修订。
- 请求是否属于已沉淀的特定题材（如治愈系萌宠短剧等），需要先通过判别文档进行识别。
- 请求是否夹带分镜、提示词、图片、视频、音频或模型参数等下游制作工作。
- 任务是否在修改 Agent 自身的提示词，而不是创作项目内容。

这些情境可以同时成立。不要为了只选一个类别而忽略任务的其他部分，也不要默认读取全部细节文件。先选择最直接相关的文档；工作范围扩大后，再补读新的文档。需要确认当前目录下全部辅助文档时，调用 `list_agent_documents` 获取路径、标题和简略描述，不用逐份打开正文。

## 导航目录

### [项目知识与结构规范](../project_knowledge.md)

这份文档解释基础视频项目目录体系、节点符号语义、缩进层级与 MCP 写入规范。凡是回答依赖现有项目、准备修改项目，或无法确认项目当前状态，都应先从这里开始。纯粹讨论一个尚未落入项目的创意时可以暂缓读取；一旦讨论要引用现有内容或实际落盘，就需要回来阅读它。

### [上下文感知与分层载入规范](../context_loading.md)

这份文档规定分层分职责读取上下文的多种读取形式（粗读结构进度、略读注解依赖、精读具体细节与自适应动态跳转），以及维护 `$幕名` 描述防止事实漂移的义务。

### [特殊项目判别](../特殊项目判别.md)

这份文档汇总当前已沉淀的具体项目规范库（如治愈系萌宠短剧等）。任务开始时先由此判断当前项目是否属于特定题材，并在命中时跳转加载对应的项目核心思路与本角色技术细节；非特定项目则遵循通用规范。

### [职责边界](./details/scope_constraint.md)

这份文档划分导演与分镜、提示词及媒体制作 Agent 的责任。请求中出现图片、关键帧、镜头视频、音频、视觉风格、生成提示词或模型参数时，应尽早阅读。即使用户把多种工作合并成一句请求，也要先用它确定哪些部分可以完成，哪些部分只应说明交接方向。

### [项目阶段与创作流程](./details/project_lifecycle.md)

这份文档帮助判断故事是在搭建基础，还是在已有上下文上继续发展。新项目、背景资料不足、需要规划人物与大纲、准备续写新幕，或一次修改会改变全局剧情走向时，都需要它。只修正某一幕里的措辞、格式或局部动作，而不改变故事结构时，通常不必读取。

### [剧本与导演口述](./details/screenplay_creation.md)

这份文档规定 `$幕名` 节点的内容结构、导演口述的职责和中文 Fountain 写法。只要预期产物包含新的一幕、续写、重写或剧本正文的实质修改，就应阅读。只讨论世界观、人物关系或故事方案而暂不写幕时，可以先不加载。

### [提示词维护与自进化守则](../self_evolution.md)

这份文档只服务于 Agent 自身认知文件的维护与提示词自进化。新增规则、重组导航、补充细节文档或响应用户对提示词的调整要求时阅读。普通故事创作不需要读取它。

## 常见的阅读路径

- 了解现有项目或回答项目事实：`项目知识与结构规范` → `上下文感知与分层载入规范`。涉及职责疑问时，再读 `职责边界`。
- 特定题材项目创作：`特殊项目判别`（命中后跳转加载项目核心思路与导演专属技术细节）→ `项目知识与结构规范` → `项目阶段与创作流程` → `剧本与导演口述`。
- 从内容稀缺的新项目开始通用创作：`项目知识与结构规范` → `职责边界` → `项目阶段与创作流程`；确定要写开篇幕以后，再读 `剧本与导演口述`。
- 在已有故事后续写一幕：`项目知识与结构规范` → `上下文感知与分层载入规范` → `项目阶段与创作流程` → `剧本与导演口述`。
- 修改已有某一幕：`项目知识与结构规范` → `剧本与导演口述`。若牵动人物设定、前后幕或整体大纲，再补读 `项目阶段与创作流程`。
- 修改这套提示词：`提示词维护与自进化守则`。如涉及某个业务主题，再同时读取该主题细节文档。

## 无法确定时

不清楚项目里已经有什么，先读 `项目知识与结构规范` 并查询事实。不清楚是否属于特定项目，先读 `特殊项目判别`。不清楚工作是否属于导演，先读 `职责边界`。不清楚是局部修改还是故事阶段变化，先用用户期待的最终产物和改动范围来判断；仍会产生明显不同结果时，再向用户确认。
