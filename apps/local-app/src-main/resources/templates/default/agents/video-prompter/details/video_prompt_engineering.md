# 视频镜头提示词

视频 Prompt 描述一段变化，而不是静态关键词。自然段落依次写可见起始状态、主体动作轨迹、摄影机运动、环境反馈、速度节奏和落幅状态。专业运镜与光学术语可以使用英文，其余叙事保持清楚自然。资产与关键帧引用负责稳定静态事实，正文不重复它们已定义的外观。

## 按输入方式组织

单场景视频在开头自然交代真实场景引用和必要布局一次，之后专注动作和运镜。空间跨越或转场只在发生处写出真实场景引用与动作接点。图生、多关键帧或参考视频任务已有视觉起点，重点写输入之后的动作轨迹、镜头位移、光线变化和落幅状态，不复述输入画面的全部静态内容。首尾帧插值应把变化路径写清。纯文字视频则先建立空间、主体和初始状态，再说明连续运镜与环境动态。

引用场景、角色或风格节点时使用工具返回的真实 ID，并确认它们确实属于目标依赖。相邻镜头连续生成时，明确继承的动作方向、人物状态、构图或时空关系；具体连续性优先于泛泛的“保持一致”。

## 连续镜头与硬切

连续运镜不使用时间戳，以连贯段落表达起始状态、动作发力、摄影机轨迹、道具交互与落幅。存在明确 Hard Cut 的组合镜头按切点分段；每段仅以纯时间范围开头，例如 `[0:00-0:04]`，随后直接写景别、视点、动作和衔接，不写镜头编号、标题或解释性副标题。独立音频资产由 `image-prompter` 编写与维护，视频 Prompt 只在镜头需要与已挂载声音同步时说明可观察的对位，不重写音色、对白、拟音或配乐内容。

## 时长与完成度

短镜头集中一个清楚变化，较长镜头才承担多阶段动作。动作幅度、人物位移和摄影机轨迹必须能在所选时长完成。`Dolly In / Out`、`Truck Left / Right`、`Pan Left / Right`、`Tilt Up / Down`、`Tracking Shot`、`Arc Shot`、`Orbit Shot`、`Rack Focus` 与 `Zoom` 只在服务镜头时使用，并融入完整叙述。允许时长、分辨率、宽高比、参考数量和输入模式通过 `list_generation_models` 的目标 `modelId` 核验，不把旧档位当作当前事实。

写入前确认没有 Markdown 装饰或解释性前缀；写入后回读字段，核验动态完整、引用有效、参数符合当前模型契约。
